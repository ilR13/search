# Поисковый сервис по текстам документов

Небольшой HTTP-сервис на **FastAPI**, который ищет по тексту документов через **Elasticsearch** и отдаёт полные записи из **SQLite**.

- `GET /search?query=...` — полнотекстовый поиск, возвращает первые 20 документов (все поля БД), упорядоченные по дате создания.
- `DELETE /posts/{doc_id}` — удаляет документ из БД и из поискового индекса.

Документация API: `docs.json` (OpenAPI) в корне проекта, интерактивная версия (Swagger UI) — `http://localhost:8000/docs` на запущенном сервисе.

---

## Как это устроено

| Хранилище | Что хранит | Зачем |
|---|---|---|
| SQLite (`posts.db`) | `id`, `rubrics`, `text`, `created_date` | источник данных, выдача полных записей |
| Elasticsearch (индекс `posts`) | `id`, `text` | быстрый поиск по тексту |

Схема работы поиска:

1. Запрос пользователя ищется в поле `text` индекса (анализатор `russian`, то есть учитываются формы слов: «конкурсы» найдёт «конкурс»).
2. Elasticsearch возвращает `id` подходящих документов.
3. По этим `id` из SQLite берутся полные записи, сортируются по `created_date` по убыванию (сначала новые), остаются первые 20.

Схема индекса: `id` (integer), `text` (text, analyzer `russian`). Документ в индексе хранится под `_id`, равным `id` из БД.

---

## Требования

- Docker (Docker Desktop на Windows/macOS или Docker Engine на Linux)
- Свободные порты `9200` (Elasticsearch) и `8000` (сервис)

Всё остальное (Python, зависимости) ставится внутри образа.

---

## Запуск в Docker

Команды выполняются из корня проекта.

### 1. Файл настроек `.env`



```
ELASTIC_LOGIN=elastic
ELASTIC_PASSWORD=<ваш_пароль>
ELASTICSEARCH_URL=https://elastic:9200
```

Важно:

- пароль в `.env` должен **совпадать** с паролем, который вы зададите контейнеру Elasticsearch в шаге 3;
- `elastic` в адресе — это имя контейнера Elasticsearch из шага 3, внутри сети Docker контейнеры обращаются друг к другу по имени;
- необязательные переменные: `SQLITE_FILE` (по умолчанию `posts.db`), `CSV_FILE` (по умолчанию `posts.csv`).

### 2. Docker-сеть

```bash
docker network create my_network
```

### 3. Elasticsearch

```bash
docker run -d --name elastic --network my_network -p 9200:9200 -e "ELASTIC_PASSWORD=<ваш_пароль>" -e "discovery.type=single-node" elastic/elasticsearch:8.19.22
```

Elasticsearch стартует 30–60 секунд. Дождитесь готовности

### 4. Сборка образа сервиса

```bash
docker build -t myapp:v1.0 .
```

### 5. Запуск сервиса

```bash
docker run -d --name myapp --network my_network -p 8000:8000 --env-file .env myapp:v1.0
```

### 6. Загрузка данных

Один раз после запуска, пока Elasticsearch уже готов:

```bash
docker exec myapp python load_data.py
```

Скрипт:

- создаёт индекс `posts` с нужным маппингом, если его нет;
- создаёт БД SQLite из `posts.csv`, если таблицы ещё нет;
- отправляет в индекс пары `id` + `text` пачкой (bulk).

Скрипт можно запускать повторно: индекс не пересоздаётся, документы в индексе перезаписываются по тому же `_id`, дублей не будет.

### 7. Проверка

Откройте `http://localhost:8000/docs` или выполните запрос из раздела «Примеры».

## API

### `GET /search`

Поиск по тексту документов.

| Параметр | Где | Тип | Описание |
|---|---|---|---|
| `query` | query-строка | string, обязательный | произвольный текстовый запрос |

Ответы:

| Код | Когда |
|---|---|
| `200` | список документов (до 20 штук, может быть пустым `[]`) |
| `422` | параметр `query` не передан |
| `503` | Elasticsearch недоступен |

Формат элемента ответа (значения для примера):

```json
{
  "id": 17,
  "rubrics": "['VK-1', 'VK-2']",
  "text": "Текст документа...",
  "created_date": "2019-07-25 12:42:13"
}
```

### `DELETE /posts/{doc_id}`

Удаляет документ из БД и из индекса.

| Параметр | Где | Тип | Описание |
|---|---|---|---|
| `doc_id` | путь | integer | `id` документа |

Ответы:

| Код | Когда |
|---|---|
| `200` | `{"message": "Document Deleted"}` — документ удалён |
| `200` | `{"message": "Document Not Found Database"}` — в БД такого документа нет |
| `422` | `doc_id` не является целым числом |
| `503` | Elasticsearch недоступен |

Удаление идемпотентно: повторный вызов с тем же `doc_id` ничего не ломает. Запись из индекса удаляется в любом случае; отсутствие записи в индексе ошибкой не считается.

## Примеры

Поиск:

```bash
curl -G "http://localhost:8000/search" --data-urlencode "query=конкурс"
```

Удаление:

```bash
curl -X DELETE "http://localhost:8000/posts/17"
```

## Принятые решения и ограничения

- **Поиск по любому из слов.** Запрос из нескольких слов находит документы, где встречается хотя бы одно из них (оператор `OR`, поведение `match` по умолчанию).
- **Сортировка по дате применяется ко всем найденным документам**, а не к топ-20 по релевантности: из индекса берутся все подходящие `id` (до 10 000), из БД выбираются 20 самых свежих. Даты хранятся строкой в формате `YYYY-MM-DD HH:MM:SS`, поэтому строковая сортировка совпадает с хронологической.
- **`rubrics` отдаётся строкой**, в том виде, в каком хранится в БД (SQLite не поддерживает массивы).
- **Сертификат Elasticsearch не проверяется** (`verify_certs=False`): в Docker используется самоподписанный сертификат, а сервис и Elasticsearch работают в изолированной сети. Для боевого окружения нужно настроить.
- **Согласованность хранилищ.** Две системы не связаны транзакцией. При удалении документ сначала удаляется из БД, затем из индекса. Если Elasticsearch станет недоступен между этими шагами, в БД документ уже будет удалён, а клиент получит `503`; в индексе останется запись, которая при поиске не попадёт в выдачу (её нет в БД). Повторный `DELETE` после восстановления Elasticsearch очистит индекс.

## Обновление `docs.json`

Файл — снимок схемы запущенного сервиса. После любых изменений API сформируйте его заново:

```bash
curl http://localhost:8000/openapi.json -o docs.json
```
